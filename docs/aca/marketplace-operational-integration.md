# Operational integration gate
Default disabled. Enable only after trusted issuer and membership mapping are verified. Configure ACA_MARKETPLACE_ENABLED, ACA_MARKETPLACE_RESOURCE, ACA_MARKETPLACE_ISSUER, ACA_MARKETPLACE_ORIGIN and ACA_MARKETPLACE_PUBLIC_KEY via approved runtime configuration. No credentials provisioned. Existing HS256 business login is not an OAuth issuer; reuse active aca_business_identities membership at the issuer boundary. Require authorization code with PKCE, exact redirect validation, scoped RS256 tokens, expiry, revocation policy and verified tenant mapping. No compatible zero-cost issuer verified yet. Do not enable until live positive and negative reviewer cases pass in controlled staging. Rollback: disable flag and restore prior deployment. CAP-001.

## Authorization core (disabled, not mounted)
The separate oauthAuthorization module accepts only an existing verified-business login token and exact configured client, HTTPS redirect, resource and scope. An authenticated consent UI with CSRF protection must precede authorize(); no anonymous route may invoke it. The code is hashed at rest, expires in two minutes and is atomically consumed only with matching S256 verifier and active membership. Access tokens expire in five minutes. No refresh token is issued. The issuer signing key must match the pinned resource-server verification key; custody and rotation remain operational prerequisites. The draft code-table migration is not applied. Verify issuer role privileges (including identity SELECT and code INSERT/SELECT/DELETE), resource role read-only membership/profile permissions and expired-code cleanup before activation. No grants or credentials are created by this candidate. Actual client registration, consent/authorization HTTP endpoints, token endpoint, issuer metadata, rate limiting, and hosted interoperability remain outstanding. Do not publish or activate on the basis of unit tests alone.
